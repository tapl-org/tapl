# Plans

Each plan is one design change, carried out in steps of one commit each. A plan is
**open** until every step is done, and then **closed**, with its status set to
**implemented**, and moved to [implemented/](implemented/).

## Open

| Plan | Status | Description |
|---|---|---|
| [plan_c_interop.md](plan_c_interop.md) | proposed, with open questions; 0 of 9 phases | Roadmap, each phase a plan of its own: Anvil, a new two-layer language whose layer 0 (what runs) and layer 1 (the type checker, run at compile time by JIT) each lower to oymomo, BANF and LLVM, and that calls C and is called by C. Covers its name and syntax, the oymomo gaps (memory, `void`, floats, function pointers, varargs), C ABI lowering in `llvm_abi.py`, and header import with libclang. |
| [plan_confluence.md](plan_confluence.md) | proposed, with open questions; 0 of 4 steps | Reduction order doesn't change the result: any two full-β reductions can be joined. Beta stops stripping the argument's form and a new rule `(t~G)~F → t~F` replaces it. Built-in rules must commute with reduction of their argument. A test-only full-β reducer checks that every strategy, `whnf` and `shape` included, gives the same normal form. |
| [plan_floats.md](plan_floats.md) | proposed, with open questions; 0 of 5 steps | `'f32'` and `'f64'` as LLVM's `float` and `double`, literals as their IEEE 754 bits. Arithmetic, comparisons (one symbol per predicate, `'fcmp_olt'` as `'icmp_slt'`), conversions and exact intrinsics as opcodes polymorphic in `form`. LLVM's default environment: round to nearest even, no fast-math; reduction folds bit-exactly but never to a NaN; transcendental functions are libm imports. |
| [plan_memory.md](plan_memory.md) | proposed, with open questions; 0 of 5 steps | Memory as in LLVM: a `'ptr'` form (LLVM's opaque `ptr`), and `'alloca'`, `'getelementptr'`, `'load'`, `'store'` as in LLVM (opcodes, see plan_vm.md), one instruction each, taking the form as a value where LLVM takes a type, no bounds checks. Memory ops are effects, ordered by hand with `$after {x, d1, ...}`, an identity reduction can't see through that `convert` drops; it orders calls to imports too. Tests pin down what full β does to effects without `$after`. Arrays, vectors and packed structs are tagged pairs (`{'array', {element, count}}`) that only BANF and LLVM read. Reduction never folds a memory op; LLVM does. Compared with Cranelift's memory model. Open: checking order, globals, alignment, aliasing. |
| [plan_vm.md](plan_vm.md) | paused, with open questions; 1 of 6 steps | Spindle, a tiny embeddable VM that runs verified BANF in Python, written so a C port is a straight translation: a stack bytecode as Wren's, a pure interpreter checked once at load as wasm3, and state that is host objects as Lua's (`Spindle`, `Fiber`): the host creates and resumes fibers, host functions yield them and call back into the VM recursively, and a yield crosses a host call by a continuation (Lua 5.2's `lua_callk`). The core knows only integers, control flow and calls; structs, memory and coroutines are host functions. Every operation is a VM symbol, `'name' {args}`, from one table read by reduction (folds pure ones on literals), the VM and LLVM. Breaking: opcodes become VM symbols polymorphic in `form` (`$add_i32 {a, b}` → `'add' {'i32', a, b}`, fields positional in LLVM's order, labels ignored; `$slt_i32` → `'icmp_slt'`); `$` stays only for `$fix`, `$struct_to_fields`, `$fields_to_struct`, `$after`. Memory laid out as LLVM lays it out. |

## Closed

| Plan | Description |
|---|---|
| [plan_switch.md](implemented/plan_switch.md) | A struct of jumps applied to a run-time index jumps to the field at that index; an index past the last field selects the last field, in reduction and in BANF. In tail position, two fields are a `Branch` and three or more a BANF `Switch`, lowered to an LLVM `switch` whose default is the last target. A switch may repeat a target with the same args. |
| [plan_constant_folding.md](implemented/plan_constant_folding.md) | An opcode whose operands are all literals reduces to its result (`$add_i32` on `[01000000]` and `[02000000]` is `[03000000]~'i32'`), with the bytes LLVM would compute and nothing folded where LLVM has no defined result. Each opcode gets a rule in `reduction.BUILTIN_RULES`. |
| [plan_struct_pack.md](implemented/plan_struct_pack.md) | `$struct_to_fields s` turns a struct into a list of fields (`{more, label, value, rest}` nodes) and `$fields_to_struct l` turns one back, so a struct can be built dynamically: labels and number of fields computed by oymomo code. First, a built-in reduces its own call: `BuiltinRule.reduce(call, reduce_part)` reduces the parts of its argument it reads, so `banf_shape` needs one case for every built-in. |
| [plan_if_as_struct_apply.md](implemented/plan_if_as_struct_apply.md) | `if c then t else e` is sugar for `{e, t} c`: a struct applied to the condition, which reduction already handles. The printer prints a two-field unlabeled struct apply as `if`. In BANF, a struct literal applied to an atom in tail position is a `Branch`. The `If` term goes; the syntax stays. |
| [plan_builtin.md](implemented/plan_builtin.md) | Every primitive is a global constant written `$name` (`$add_i32`, `$fix`), so the program has no `prim ->` binder and `fix` is no longer a term or keyword. A built-in has a reduction rule in `reduction.BUILTIN_RULES`, an opcode, or both; a strict rule's argument is reduced first. `s [01]` on a value struct is the BANF op `GetIndex`. |
| [plan_struct_apply.md](implemented/plan_struct_apply.md) | A struct applied to an index selects the field (`s [01]`), so a field can be picked by a position computed at run time. Field labels are optional, so a struct can be a tuple. In BANF, `prim.extractvalue` reads a field of a value struct by its index; step 1 of `plan_builtin.md` replaces it with the op `GetIndex` (`s [01]`). |
| [plan_banf_explicit.md](implemented/plan_banf_explicit.md) | BANF translation has no defaults: it only reduces terms, infers nothing, and drops unneeded forms. A written form replaces a computed one, since a form is not a type. |
| [plan_annotation.md](implemented/plan_annotation.md) | No enforced parentheses: any syntax has a meaning based on precedence. `e : F` is a `Formed` term, so any term, a form included, can come from an expression. |
| [plan_term_as_form.md](implemented/plan_term_as_form.md) | Forms are plain terms (`'i32'`, `{x = 'i32'}`, `{c = 'i8'} => 'i32'`), written with the same syntax as any other term instead of a separate form grammar. |
